# HW6 Problem 2 — Handbook token 数与成本估算

> 本文件是**估算**，不是 API 实测数据。第 4 题会用真实调用的 usage 数据来核对这里的数字。

## 1. Token 数量

| 项目 | 数值 |
|---|---|
| 文件 | `data/shop_handbook.md`（完整文件，29,241 bytes / 28,903 字符） |
| **Token 数（o200k_base，本文采用）** | **10,058** |
| 对照：cl100k_base | 10,184 |

### 统计方法

- 工具：OpenAI 官方开源 tokenizer 库 `tiktoken` 0.14.0（Python）。
- 做法：以 UTF-8 读入整份手册，不做任何删减或改写，调用 `tiktoken.get_encoding("o200k_base").encode(text)`，结果列表的长度就是 token 数。用 cl100k_base 也算了一遍作对照。
- 脚本：[`scripts/count_handbook_tokens.py`](../scripts/count_handbook_tokens.py)，运行 `python scripts/count_handbook_tokens.py` 可复现。
- 没有用“字符数 ÷ 4”这种经验估计。（作为参照，28,903 ÷ 4 ≈ 7,226，比真实分词结果少约 28%，说明这个经验值在这份手册上偏差很大。）

### 限制：为什么说是估算

- `gpt-6-luna` 的 tokenizer **无法确认**：tiktoken 里没有这个模型名称的映射。我选用 **o200k_base**，因为它是 OpenAI 当前 GPT-4o / GPT-5 系列模型使用的编码，是最接近的公开替代。
- 两种编码只差 126 个 token（约 1.3%），说明结果对编码选择不太敏感，但真实数字仍可能略有不同。
- 这里只统计**手册正文**。真实 API 调用中，消息格式本身会多出几个 token（role 标记等），系统提示、供应商文档和工具定义也会额外计费，这些都**不包含**在本估算里。

## 2. 价格依据

来源：`data/prices.json` 中的 `gpt-6-luna`（文件注明来源为 "OpenAI Standard pricing, per 1M tokens (MGT 409 Lecture 11)"）。单位都是**美元 / 每 1,000,000 token**。

| 价格项 | 单价（USD / 1M tokens） | 本题是否使用 |
|---|---|---|
| 普通输入 `input_per_1m` | $0.10 | 是 |
| 缓存输入（命中/读取）`cached_input_per_1m` | $0.01 | 是 |
| 缓存写入 `cache_write_per_1m` | $0.125 | 只用于第 4 节的首次写入说明 |
| 输出 `output_per_1m` | $0.50 | 否（本题不算输出） |

## 3. 计算公式与结果

范围：**只算手册本身的输入成本**，不包含其他提示词、供应商文档、工具定义或模型输出。

- 无缓存单次费用 = 10,058 ÷ 1,000,000 × $0.10 = **$0.0010058**
- 缓存命中单次费用 = 10,058 ÷ 1,000,000 × $0.01 = **$0.00010058**
- 1,000 次费用 = 对应单次费用 × 1,000

| 情况 | 调用次数 | 计算 | 费用（USD） |
|---|---|---|---|
| 不使用缓存 | 1 | 10,058 / 1,000,000 × 0.10 | **$0.0010058** |
| 不使用缓存 | 1,000 | 0.0010058 × 1,000 | **$1.0058** |
| 手册全部命中缓存 | 1 | 10,058 / 1,000,000 × 0.01 | **$0.00010058** |
| 手册全部命中缓存 | 1,000 | 0.00010058 × 1,000 | **$0.10058** |

结论：在这个价格表下，缓存命中让手册部分的输入成本降到原来的 **1/10**。1,000 次调用约节省 $1.0058 − $0.10058 = **$0.90522**。

## 4. 假设与首次建立缓存的成本

- **缓存表的假设：** 上表中的“全部命中缓存”假设**每一次**调用（包括第 1 次）中，手册的全部 10,058 个 token 都按缓存读取价计费。这是理想情况的下限，实际上第一次调用不可能命中缓存。
- **首次写入是另一项费用：** `prices.json` 列出了缓存写入价 $0.125 / 1M，比普通输入价 $0.10 还贵。这一项不能和后续的缓存读取混在一起：
  - 首次写入缓存（1 次）= 10,058 ÷ 1,000,000 × $0.125 = **$0.00125725**
  - 更现实的 1,000 次组合 = 1 次写入 + 999 次命中 = $0.00125725 + 999 × $0.00010058 = **$0.10173667**
  - 和“1,000 次全部命中”的 $0.10058 相比只多出约 $0.0012，所以写入成本会被后续的命中很快摊薄。
- **其他假设：**
  - 缓存在两次调用之间没有过期。
  - 手册放在提示词最前面，并且每次内容完全一致，这样前缀才能命中缓存。
  - 实际服务商可能对可缓存的最小前缀长度和缓存粒度有要求，所以真实命中的 token 数可能略少于 10,058。
  - 实际是否命中、命中多少，以第 4 题 API 返回的 `cached_tokens` 为准。
